## 最新反馈修订：鸡肉串与冬阴功使用 v3

- 鸡肉串：先对原始实录进行频谱降噪和平滑向下扩展，压低咬合间隙；轻补 700–2400 Hz 的咬合细节。播放增益维持 0.55，不继续整体加大。使用 `satay/v3/`，旧版保留。
- 冬阴功：不再每口纯啜汤。前段以柔软固体为主，中间交错喝汤，末段以汤为主。前 3 口的固体层比例依次为 90%、82%、38%，后续阶段穿插变化，最后一口降至 6%。这是音频混音比例，不代表模型中虾仁含量。
- 固体层使用去噪软鸡肉口腔录音作拟音替代，并非真正的虾仁实录；未找到合适的虾仁专门实录，因此明确保留此限制。每段两种来源及比例记录在 `tom-yum/v3/manifest.json`。
- 当前来源说明以被映射的 `v3/SOURCE.md` 或 `v2/SOURCE.md` 为准，上表冬阴功的纯啜汤方案属于上一版。

## 单独提交与部署

本项目所有实际播放文件都在自身 `public/audio/tasting/`，映射在自身 `src/data/eating-audio.json`，应用代码不读取另一个项目或工作区音效库。Vite 构建会原样复制到 `dist/audio/tasting/`。保留 MP3 和对应 SOURCE.md 一起提交。

在本项目根目录执行 `npm run verify:audio` 可检查映射、文件与 SHA-256；执行 `npm run build` 后，再运行 `npm run verify:audio -- --dist` 可检查构建产物中的所有音频。这些检查只依赖本项目和 Node，无需 Python、ffmpeg、另一个仓库或本地原始音效库。Python 制作工具与原始音效库仅用于作者本地重制，不参与运行或部署。

每道菜的 `v2/SOURCE.md` 为详细署名与授权记录；`manifest.json` 保存原始时间、混合比例、编码后响度和 SHA-256。芒果录音经过剪辑、滤波、混合、归一化；分发需保留 zebraphone 的 CC BY 4.0 署名。

每阶段四个短片段，共 64 段。剩余量带来轻微口量变化，保持原速，避免统一降低音调、低通造成不自然的“食物变质”。静音、隐藏页面、退出及待播取消沿用原机制。

制作工具在同一工作区 `foodstage-3d/tools/build_eating_audio.py`；原始录音在 `音效库/freesound`，四阶段试听在 `音效库/试听-v2`。需 ffmpeg、Python、numpy、scipy、requests。先获取原始素材，再制作、检查；这些工具按双项目工作区目录运行。

技术解码、峰值、RMS 与路径检查不能替代人工听感验收，尤其是糯米拟音替代和勺碗背景声。
